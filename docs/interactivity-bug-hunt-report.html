What actually changed

Every action that can control playback now invalidates older unfinished work before waiting on the network or browser.

1User changes playback

Remove, clear, select, pause, disable crossfade, rename, or delete a playlist.

→
2Audio and visible timing update immediately

The rejected audio pauses; old position and duration are cleared when selection changes.

→
3Older work loses permission

Playback commands and auto-play sessions use increasing freshness numbers.

→
4Late completion is checked

It applies only if the same song, queue, and command are still current; otherwise it is discarded.

Before

The screen could show the new state while an old request still controlled the audio. When that request finished, the removed song or cleared queue could return.

Now

The state change and audio stop happen together. Unfinished work may complete internally, but it cannot become audible or mutate the new queue.

Fixed behavior

Each item below had a failing regression before its production fix.

Removal

Cutting the current song stops it first

The old song no longer keeps playing while a streamed replacement takes time to resolve.

Queue clear

A late song load cannot restart after Clear

Clearing invalidates the unfinished load, so its eventual result remains silent.

Rapid selection

An older selection cannot replace a newer one

If B is selected after A, B remains audible even when A’s network response arrives last.

Auto-play

A cleared queue cannot refill itself

Recommendations fetched for an earlier queue are rejected after Clear or queue replacement.

Transport

Fast Play then Pause ends paused

The first asynchronous resume cannot flip the control back to playing after the second click.

Browser start

Pause works while playback is being confirmed

A click during the browser’s pending play response cancels that start instead of launching a second load.

Timeline

The new title no longer shows the old duration

Position and duration reset at selection time, before a replacement source is ready.

Crossfade

Removing the incoming song silences it

An overlap cannot finish into a queue item removed while it was already audible.

Crossfade setting

Turning crossfade off cancels the active overlap

The setting now affects the overlap already in progress, not only future songs.

Late crossfade

A removed or reordered target cannot start later

After source resolution, the app verifies that the same item is still actually next.

Pause + crossfade

Pause blocks a resolving incoming song

A source that returns after Pause cannot start an overlap behind the paused state.

Rename

Song names stay synchronized while playing

Library rename now updates the queue, Now Playing bar, and presence data without restarting audio.

Playlist delete

The queue stops claiming a deleted playlist

Playback continues, but the live queue detaches from the playlist record that no longer exists.
